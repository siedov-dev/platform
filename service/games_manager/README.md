# Сервис игр
Сервис используються для быстрого доступа к информации о существующих играх. Для каждого типа устройства(desktop, mobile) и локали (ru, en, ...) создается отдельнный `игровой менеджер` который хранит информацию о всех доступных играх. Так же существуют два тестовых менеджера для тест юзеров. Для использования тестовых менеджеров в качестве локали необходимо указать **test**. У каждой игры существует свой уникальный идентификатор `cid` который состоит из трех частей: *ид игровой системы/ид группы (провайдера)/ид игры в игровой системе*
Игры обновляються и выгружаються в базу на стороне сайта в задаче `RenewGamesCache`. Все настройки производяться в crm и сохраняються напрямую в БД.

# Методы
Обмен данных осуществляеться посредством запросов по http. Обработка запросов выполняется в пакете `http_server`. 

# Описание HTTP-роутов API

| Метод | Путь | Описание |
|-------|------|----------|
| GET | `/` | Проверка работоспособности сервера, возвращает "ok". |
| GET | `/ping` | Проверка соединения, возвращает "pong". |
| GET | `/reload` | Перезагрузка списка игр. |
| GET | `/byCid/{device}/{lang}/{cid}` | Получить игру по CID (уникальный идентификатор игры: система/группа/ID). |
| GET | `/byTag/{device}/{lang}/{tag}` | Получить список игр по тегу (например, hot, new и др.). |
| GET | `/byLndGroup/{device}/{lang}/{group}` | Получить список игр по лендинг-группе. |
| GET | `/games/{device}/{lang}` | Получить все игры для указанного устройства и языка. |
| GET | `/search/{device}/{lang}/{groups}/{categories}/{tags}/{name}/{per_page}/{page}` | Поиск игр по группе, категории, тегу, имени. Параметры пагинации: per_page — количество на странице, page — номер страницы. |
| GET | `/bonusGames/{device}/{lang}/{bonus_id}/{groups}/{categories}/{tags}/{name}/{per_page}/{page}` | Получить игры, доступные для бонуса, с возможностью фильтрации и пагинации. |
| GET | `/provider/{device}/{lang}/{provider}/allGames` | Получить все игры указанного провайдера для устройства и языка. |
| GET | `/provider/{device}/{lang}/{provider}/getGame/{id}` | Получить игру провайдера по ID. |
| GET | `/provider/{device}/{lang}/{provider}/getGroups` | Получить группы игр (провайдеров) игровой системы. |
| GET | `/provider/{device}/{lang}/{provider}/groupGames/{groupid}` | Получить игры группы провайдера по groupid. |
| GET | `/provider/{device}/{lang}/{provider}/getGroupGame/{groupid}/{id}` | Получить игру группы провайдера по groupid и id. |
| GET | `/provider/{device}/{lang}/{provider}/searchGames/{groups}/{categories}/{tags}/{name}/{per_page}/{page}` | Поиск игр провайдера по группе, категории, тегу, имени, с пагинацией. |

**Пояснения к параметрам:**
- `device` — устройство (например, desktop, phone)
- `lang` — язык (например, ru, en)
- `cid` — уникальный идентификатор игры
- `tag` — тег игры (hot, new и др.)
- `groups`, `categories`, `tags` — фильтры поиска (можно передавать через запятую, могут быть пустыми)
- `name` — название игры, либо частичное название игры при поиске
- `per_page`, `page` — параметры пагинации
- `bonus_id` — идентификатор бонуса
- `provider` — идентификатор провайдера
- `groupid` — идентификатор группы провайдера
- `id` — идентификатор игры в системе игрового провайдера

При указании page=0 будут возвращены все игры.

# Ответы

**GamesResponse**  
Структура для формирования ответа на запросы, связанные с играми.

Поля:
- `Status int` — статус HTTP-ответа (например, 200 — успех, 400 — ошибка клиента, 404 — не найдено, 500 — ошибка сервера).
- `Error string` — сообщение об ошибке, если она произошла.
- `GamesTotal int` — общее количество игр, подходящих под запрос.
- `PagesTotal int` — общее количество страниц (для пагинации).
- `Page int` — номер текущей страницы.
- `Data interface{}` — данные ответа (например, список игр или информация об одной игре, в зависимости от типа запроса).

**Примечание:**  
Структура используется для всех игровых эндпоинтов API и позволяет возвращать как списки игр, так и отдельные объекты, а также информацию о статусе и ошибках.

        "p":"sleg", // игровая система

        "id":"f868bdcd4d71ed1b1fc197405c60f48db19f4568", // ид игры

**SearchResponse**  
Структура для формирования ответа на запросы поиска игр.  
Аналогична `GamesResponse` за исключением дополнительной информации о списке игровых групп к которым относяться найденые игры.

Поля:
- `Status int` — статус HTTP-ответа (например, 200 — успех, 400 — ошибка клиента, 404 — не найдено, 500 — ошибка сервера).
- `Error string` — сообщение об ошибке, если она произошла.
- `GamesTotal int` — общее количество игр, подходящих под условия поиска.
- `PagesTotal int` — общее количество страниц (для пагинации).
- `Page int` — номер текущей страницы.
- `Groups games_t.GamesGroupsSet` — группы игр, подходящие под условия поиска.
- `Data interface{}` — данные ответа (например, список найденных игр или информация об одной игре, в зависимости от типа запроса).

**Примечание:**  
Структура используется для всех поисковых эндпоинтов API и позволяет возвращать как списки игр, так и отдельные объекты, а также информацию о группах, статусе и ошибках.

**ReloadResponse**  
Структура для формирования ответа на запрос перезагрузки данных.

Поля:
- `Status int` — статус HTTP-ответа (например, 200 — успех, 400 — ошибка).
- `Error string` — сообщение об ошибке, если она произошла.
- `Time string` — время, затраченное на перезагрузку (в секундах, строкой). Если произошла ошибка, поле может быть пустым.

**Пример успешного ответа:**  
`{"status":200,"error":"","time":"0.123456789"}`

**Пример ответа с ошибкой:**  
`{"status":400,"error":"ошибка перезагрузки","time":""}`

**GroupResponse**  
Структура для формирования ответа с группами игр.

Поля:
- `Status int` — статус HTTP-ответа (например, 200 — успех, 400 — ошибка).

- `Data []games.GroupInfo` — данные: список групп игр (структуры `GroupInfo` из пакета `games`).

**Примечание:**  
Используется для возврата информации о группах игр в API.

# Описание репозиториев

В проекте используются следующие репозитории для работы с данными:

**GameConfigRepository**  
Интерфейс для работы с конфигурациями игр (основная таблица со всеми играми).  
Позволяет получить список всех игр из базы данных.  
Метод:  
- `GetGameConfigs() ([]models.GameConfig, error)`

**DisabledGamesRepository**  
Интерфейс для работы с отключёнными играми.  
Используется для получения списка игр, которые временно недоступны или находятся в тестовом режиме.  
Метод:  
- `GetDisabledGames() ([]models.DisabledGame, error)`

**LandingGamesRepository**  
Интерфейс для работы с играми, отображаемыми на лендинге а так же установка соответствующих тэгов.  
Позволяет получить список игр, которые должны быть показаны на главной странице и выставить тэги для игр.  
Метод:  
- `GetLandingGames() ([]models.LandingGames, error)`

**UserBonusRepository**  
Интерфейс для работы с бонусами пользователей.  
Используется для для выбора игр, доступных по бонусу.  
Метод:  
- `ById(id int) (*models.UserBonus, error)`

**BonusDisabledCIDsRepository**  
~~Интерфейс для работы с играми, отключёнными по типу бонуса.~~
~~Позволяет получить список игр, которые недоступны для определённых бонусов.~~  
Интерфейс для работы с играми по умолчанию по типу бонуса.
Метод:  
- `GetDisabledGamesCIDs() ([]models.BonusDisabledGames, error)`

**GropPriorityRepository**  
Интерфейс для работы с приоритетами групп игр.  
Используется для получения приоритетов групп из базы данных, чтобы сортировать группы игр.  
Метод:  
- `GetPriorities() ([]models.GameGroupPriority, error)`

---

Для получения конкретной реализации репозитория используйте функцию вида `Get<Name>Repository()`, например:  
- `GetGameConfigsRepository()`
- `GetDisabledGamesRepository()`
- `GetLanfingGamesRepository()`
- `GetUserBonusRepository()`
- `GetBonusDisabledCIDsRepository()`
- `GetGropPriorityRepository()`

# База данных
В своей работе сервис использует следующие таблицы/модели:

**BonusDisabledGames**  
~~Структура для хранения информации об играх, отключённых по определённым бонусам.~~  
Структура для хранения информации об играх по умолчанию для определенного типа бонуса.
Таблица: `bonus_disabled_games`

Поля:
- `ID int64` — уникальный идентификатор записи.
- `BonusType int16` — тип бонуса, для которого игра отключена.
- `CID string` — идентификатор игры (CID), которая отключена для данного бонуса.

**DisabledGame**  
Структура для хранения информации об отключённых играх.
Таблица: `disabled_games`

Поля:
- `ID int64` — уникальный идентификатор записи.
- `Device string` — устройство, для которого игра отключена (например, desktop, phone).
- `Type string` — тип отключения или категория (например, временно, по региону и т.д.).
- `CID string` — идентификатор игры (CID), которая отключена.

**GameConfig**  
Структура для хранения информации о конфигурации игр.

Поля:
- `ID int64` — уникальный идентификатор записи в базе данных.
- `CID string` — уникальный идентификатор игры (CID).
- `System string` — игровая система.
- `Group sql.NullString` — группа или провайдер игры (может быть пустым).
- `GameID string` — идентификатор игры в игровой системе.
- `Name sql.NullString` — название игры (может быть пустым).
- `Img sql.NullString` — URL изображения игры (может быть пустым).
- `Category sql.NullString` — категория игры (может быть пустой).
- `LandingCategory sql.NullString` — категория игры на лендинге (может быть пустой).
- `LandingGroup sql.NullString` — группа игры на лендинге (может быть пустой).
- `Title sql.NullString` — заголовок игры (может быть пустым, используется вместо названия).
- `DeviceType sql.NullString` — тип устройства (мобильный, десктоп, any; может быть пустым).
- `CustomImg sql.NullString` — URL кастомного изображения игры (может быть пустым).

**GameGroupPriority**  
Структура для хранения информации о приоритете групп (провайдеров) игр.
Таблица: `game_group_priorities`

Поля:
- `SystemId string` — идентификатор игровой системы.
- `GroupId string` — идентификатор группы (провайдера) игры.
- `Priority int` — приоритет группы (чем выше значение, тем выше приоритет).

**GameGroupPriority**  
Структура для хранения информации о приоритете групп (провайдеров) игр.

Поля:
- `SystemId string` — идентификатор игровой системы.
- `GroupId string` — идентификатор группы (провайдера) игры.
- `Priority int` — приоритет группы (чем выше значение, тем выше приоритет).

**LandingGames**  
Структура для хранения информации об играх, отображаемых на лендинге а так же тэгах.
Таблица: `landing_games`

Поля:
- `ID int64` — уникальный идентификатор записи.
- `Type string` — тип игры на лендинге/tag.
- `Lang string` — язык, для которого предназначена игра.
- `CID string` — идентификатор игры (CID).

**UserBonus**  
Структура для хранения информации о бонусах пользователей.  
Если поля с играми пусты то должен использоватся набор игр по умолчанию для данного типа бонуса.
Таблица: `users_bonuses`

Поля:
- `Id int` — уникальный идентификатор бонуса.
- `UserId int` — идентификатор пользователя, которому принадлежит бонус.
- `Type int` — тип бонуса.
- `AllowedGames sql.NullString` — список разрешённых для бонуса игр (в формате JSON, может быть пустым).
- `GameProvider sql.NullString` — провайдер игры, связанный с бонусом (может быть пустым).
- `GameID sql.NullString` — идентификатор игры, связанный с бонусом (может быть пустым).

Методы:
- `GetGames() (BonusGames, error)` — возвращает список игр, доступных для бонуса, распарсив поле `AllowedGames` из JSON. В случае отсутствия данных или ошибки парсинга возвращает ошибку.

Дополнительно:
- **BonusGames** — тип, представляющий собой карту, где ключ — строка (например, категория или провайдер), а значение — срез строк с идентификаторами игр.
