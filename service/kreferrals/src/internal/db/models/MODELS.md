# Документация моделей данных реферальной системы

## Обзор

Пакет `models` содержит структуры данных для реферальной системы приложения. Все модели представляют собой Go структуры, которые используются для работы с базой данных и JSON сериализации.

---

# 1. ReferralAchievementReward

## Описание

Модель `ReferralAchievementReward` представляет собой структуру для хранения наград за достижения рефералов. Она содержит информацию о награде, связанной с определённым достижением реферала.

## Структура

```go
type ReferralAchievementReward struct {
    ID            uint64     `json:"id" db:"id"`
    AchievementID uint64     `json:"achievement_id" db:"achievement_id"`
    RewardSums    string     `json:"reward_sums" db:"reward_sums"`
    CreatedAt     *time.Time `json:"created_at" db:"created_at"`
    UpdatedAt     *time.Time `json:"updated_at" db:"updated_at"`
}
```

## Поля

| Поле | Тип | Описание | JSON | DB |
|------|-----|----------|------|-----|
| `ID` | `uint64` | Уникальный идентификатор награды | `id` | `id` |
| `AchievementID` | `uint64` | Идентификатор достижения, к которому относится награда | `achievement_id` | `achievement_id` |
| `RewardSums` | `string` | Суммы наград в формате JSON по валютам | `reward_sums` | `reward_sums` |
| `CreatedAt` | `*time.Time` | Дата создания награды | `created_at` | `created_at` |
| `UpdatedAt` | `*time.Time` | Дата последнего обновления награды | `updated_at` | `updated_at` |

## Назначение

Модель используется для:

- Хранения информации о наградах за достижения в реферальной системе
- Связывания наград с конкретными достижениями через `AchievementID`
- Хранения сумм наград в различных валютах в JSON формате
- Отслеживания времени создания и обновления записей

## Особенности

- **JSON формат наград**: Поле `RewardSums` хранит суммы наград в формате JSON, что позволяет поддерживать множественные валюты
- **Временные метки**: Модель включает поля для отслеживания времени создания и последнего обновления
- **Связь с достижениями**: Через поле `AchievementID` награда связывается с конкретным достижением

## Использование

Модель используется в системе для:

1. Определения наград за выполнение различных достижений в реферальной программе
2. Хранения информации о суммах наград в разных валютах
3. Аудита изменений через временные метки

# 2. ReferralConfig

## Описание

Модель `ReferralConfig` представляет собой структуру для хранения конфигурации рефералов. Она содержит информацию о типе конфигурации и поддерживает три типа конфигураций:

1. **Основная конфигурация** (`ConfigTypeMain`)
2. **Промо-конфигурация** (`ConfigTypePromo`)
3. **Конфигурация пользователя** (`ConfigTypeUser`)

## Структура

```go
type ReferralConfig struct {
    ID        uint64     `json:"id" db:"id"`
    Type      int        `json:"type" db:"type"`
    UserID    uint64     `json:"user_id" db:"user_id"`
    GGRPrc    int        `json:"ggr_prc" db:"ggr_prc"`
    FdSums    string     `json:"fd_sums" db:"fd_sums"`
    StartDate *time.Time `json:"start_date" db:"start_date"`
    EndDate   *time.Time `json:"end_date" db:"end_date"`
    CreatedAt *time.Time `json:"created_at" db:"created_at"`
    UpdatedAt *time.Time `json:"updated_at" db:"updated_at"`
}
```

## Поля

| Поле | Тип | Описание | JSON | DB |
|------|-----|----------|------|-----|
| `ID` | `uint64` | Уникальный идентификатор конфигурации | `id` | `id` |
| `Type` | `int` | Тип конфигурации (ReferralConfigType) | `type` | `type` |
| `UserID` | `uint64` | Идентификатор пользователя, для конфигурации пользователя | `user_id` | `user_id` |
| `GGRPrc` | `int` | Процент GGR (Gross Gaming Revenue) | `ggr_prc` | `ggr_prc` |
| `FdSums` | `string` | Суммы FD (First Deposit) в формате JSON по валютам | `fd_sums` | `fd_sums` |
| `StartDate` | `*time.Time` | Дата начала действия конфигурации (для промо-акций) | `start_date` | `start_date` |
| `EndDate` | `*time.Time` | Дата окончания действия конфигурации (для промо-акций) | `end_date` | `end_date` |
| `CreatedAt` | `*time.Time` | Дата создания конфигурации | `created_at` | `created_at` |
| `UpdatedAt` | `*time.Time` | Дата последнего обновления конфигурации | `updated_at` | `updated_at` |

## Типы конфигураций

```go
type ReferralConfigType int8

const (
    ConfigTypeMain  ReferralConfigType = iota // 0 - Основная конфигурация
    ConfigTypePromo                           // 1 - Промо-конфигурация
    ConfigTypeUser                            // 2 - Конфигурация пользователя
)
```

### Описание типов

| Тип | Значение | Описание |
|-----|----------|----------|
| `ConfigTypeMain` | `0` | Основная конфигурация системы по умолчанию |
| `ConfigTypePromo` | `1` | Промо-конфигурация для временных акций |
| `ConfigTypeUser` | `2` | Индивидуальная конфигурация для конкретного пользователя |

## Назначение

Модель используется для:

- Хранения различных типов конфигураций реферальной системы
- Управления процентами GGR (валовой игровой доход)
- Настройки сумм первого депозита по валютам
- Управления временными промо-акциями с датами начала и окончания
- Создания индивидуальных настроек для конкретных пользователей

## Особенности

- **Гибкая типизация**: Поддержка трех различных типов конфигураций
- **JSON формат сумм**: Поле `FdSums` хранит суммы первого депозита в формате JSON для поддержки множественных валют
- **Временные рамки**: Поля `StartDate` и `EndDate` позволяют создавать временные промо-конфигурации
- **Пользовательские настройки**: Возможность создания индивидуальных конфигураций через `UserID`
- **GGR управление**: Настройка процента от валового игрового дохода

## Использование

Модель используется в системе для:

1. **Основная конфигурация**: Установка базовых параметров реферальной системы
2. **Промо-акции**: Создание временных конфигураций с особыми условиями
3. **Индивидуальные настройки**: Персонализация условий для VIP-пользователей
4. **Управление доходностью**: Настройка процентов от игрового дохода
5. **Мультивалютность**: Поддержка различных валют для первого депозита

# 3. ReferralEvent

## Описание

Модель `ReferralEvent` представляет собой структуру для хранения событий рефералов. Она отслеживает различные типы событий, происходящих в реферальной системе, включая клики, регистрации, депозиты и другие действия пользователей.

## Структура

```go
type ReferralEvent struct {
    ID          uint64     `json:"id" db:"id"`
    RefID       uint64     `json:"ref_id" db:"ref_id"`
    Type        int        `json:"type" db:"type"`
    UserID      *uint64    `json:"user_id" db:"user_id"`
    Amount      float64    `json:"amount" db:"amount"`
    Profit      float64    `json:"profit" db:"profit"`
    Currency    *int       `json:"currency" db:"currency"`
    Data        *string    `json:"data" db:"data"`
    CreatedAt   *time.Time `json:"created_at" db:"created_at"`
    UpdatedAt   *time.Time `json:"updated_at" db:"updated_at"`
    Status      int        `json:"status" db:"status"`
    ConfigID    *uint64    `json:"config_id" db:"config_id"`
    Fingerprint *string    `json:"fingerprint" db:"fingerprint"`
}
```

## Поля

| Поле | Тип | Описание | JSON | DB | Nullable |
|------|-----|----------|------|-----|----------|
| `ID` | `uint64` | Уникальный идентификатор события | `id` | `id` | Нет |
| `RefID` | `uint64` | Идентификатор реферала, к которому относится событие | `ref_id` | `ref_id` | Нет |
| `Type` | `int` | Тип события (ReferralEventType) | `type` | `type` | Нет |
| `UserID` | `*uint64` | Идентификатор пользователя, связанного с событием | `user_id` | `user_id` | Да |
| `Amount` | `float64` | Сумма, связанная с событием | `amount` | `amount` | Нет |
| `Profit` | `float64` | Прибыль, связанная с событием | `profit` | `profit` | Нет |
| `Currency` | `*int` | Идентификатор валюты события | `currency` | `currency` | Да |
| `Data` | `*string` | Дополнительные данные в формате JSON | `data` | `data` | Да |
| `CreatedAt` | `*time.Time` | Дата создания события | `created_at` | `created_at` | Да |
| `UpdatedAt` | `*time.Time` | Дата последнего обновления события | `updated_at` | `updated_at` | Да |
| `Status` | `int` | Статус события (ReferralEventStatus) | `status` | `status` | Нет |
| `ConfigID` | `*uint64` | Идентификатор конфигурации события | `config_id` | `config_id` | Да |
| `Fingerprint` | `*string` | Отпечаток пользователя, связанный с событием | `fingerprint` | `fingerprint` | Да |

## Типы событий

```go
type ReferralEventType int

const (
    ReferralEventTypeClick                        ReferralEventType = iota // 0
    ReferralEventTypeRegister                                              // 1
    ReferralEventTypeMoneySpent                                            // 2
    ReferralEventTypeDeposit                                               // 3
    ReferralEventTypeFirstDeposit                                          // 4
    ReferralEventTypeAchievementCompleted                                  // 5
    ReferralEventTypeReferralMoneyTransferred                              // 6
    ReferralEventTypeAccumulationMoneyTransferred                          // 7
)
```

### Описание типов событий

| Тип | Значение | Описание |
|-----|----------|----------|
| `ReferralEventTypeClick` | `0` | Событие перехода по реферальной ссылке |
| `ReferralEventTypeRegister` | `1` | Событие регистрации пользователя |
| `ReferralEventTypeMoneySpent` | `2` | Событие потраченных денег пользователем |
| `ReferralEventTypeDeposit` | `3` | Событие депозита |
| `ReferralEventTypeFirstDeposit` | `4` | Событие первого депозита пользователя |
| `ReferralEventTypeAchievementCompleted` | `5` | Событие завершения достижения пользователем |
| `ReferralEventTypeReferralMoneyTransferred` | `6` | Событие перевода реферальных денег пользователю |
| `ReferralEventTypeAccumulationMoneyTransferred` | `7` | Событие перевода накопительных денег пользователю |

## Назначение

Модель используется для:

- Отслеживания всех событий в реферальной системе
- Связывания событий с конкретными рефералами и пользователями
- Хранения финансовой информации (суммы, прибыль, валюта)
- Аудита действий пользователей через временные метки
- Хранения дополнительных данных в JSON формате
- Отслеживания статуса обработки событий

## Особенности

- **Гибкая типизация событий**: Поддержка множества типов событий от кликов до переводов денег
- **Nullable поля**: Многие поля могут быть NULL, что обеспечивает гибкость для различных типов событий
- **Финансовая информация**: Отдельные поля для суммы и прибыли с поддержкой валют
- **JSON данные**: Поле `Data` позволяет хранить дополнительную информацию в структурированном виде
- **Отпечатки пользователей**: Поле `Fingerprint` для идентификации пользователей
- **Связь с конфигурацией**: Возможность связать событие с конкретной конфигурацией

## Использование

Модель используется в системе для:

1. **Отслеживание кликов**: Регистрация переходов по реферальным ссылкам
2. **Регистрация пользователей**: Фиксация новых регистраций через рефералов
3. **Финансовые операции**: Отслеживание депозитов и трат пользователей
4. **Система достижений**: Регистрация выполненных достижений
5. **Переводы средств**: Учет переводов реферальных и накопительных средств
6. **Аналитика**: Сбор данных для анализа эффективности реферальной программы
7. **Аудит**: Ведение полного журнала событий для проверки и отчетности

## Жизненный цикл события

1. **Создание**: Событие создается при возникновении соответствующего действия
2. **Обработка**: Событие обрабатывается системой (изменение статуса)
3. **Завершение**: Событие помечается как завершенное после успешной обработки

# 4. UserReferral

## Описание

Модель `UserReferral` представляет собой структуру для хранения информации о рефералах (кодах) пользователей. Она содержит основную информацию о реферальных кодах, принадлежащих пользователям системы.

## Структура

```go
type UserReferral struct {
    ID           uint64     `json:"id" db:"id"`
    UserID       *uint64    `json:"user_id" db:"user_id"`
    RefCode      string     `json:"ref_code" db:"ref_code"`
    ProfitPrc    int        `json:"-" db:"profit_prc"`
    CreatedAt    *time.Time `json:"created_at" db:"created_at"`
    UpdatedAt    *time.Time `json:"updated_at" db:"updated_at"`
    BonusRefCode *string    `json:"-" db:"bonus_ref_code"`
}
```

## Поля

| Поле | Тип | Описание | JSON | DB | Nullable | Статус |
|------|-----|----------|------|-----|----------|--------|
| `ID` | `uint64` | Уникальный идентификатор реферала | `id` | `id` | Нет | Активное |
| `UserID` | `*uint64` | Идентификатор пользователя, которому принадлежит реферал | `user_id` | `user_id` | Да | Активное |
| `RefCode` | `string` | Реферальный код пользователя | `ref_code` | `ref_code` | Нет | Активное |
| `ProfitPrc` | `int` | Процент прибыли, связанный с рефералом | `-` | `profit_prc` | Нет | Устаревшее |
| `CreatedAt` | `*time.Time` | Дата создания реферала | `created_at` | `created_at` | Да | Активное |
| `UpdatedAt` | `*time.Time` | Дата последнего обновления реферала | `updated_at` | `updated_at` | Да | Активное |
| `BonusRefCode` | `*string` | Бонусный реферальный код, связанный с рефералом | `-` | `bonus_ref_code` | Да | Устаревшее |

## Назначение

Модель используется для:

- Хранения реферальных кодов пользователей
- Связывания реферальных кодов с конкретными пользователями
- Отслеживания времени создания и обновления реферальных записей
- Управления уникальными идентификаторами рефералов

## Особенности

- **Уникальные коды**: Каждый пользователь имеет уникальный реферальный код
- **Nullable UserID**: Поле `UserID` может быть NULL, что позволяет создавать реферальные коды без привязки к конкретному пользователю
- **Устаревшие поля**: Поля `ProfitPrc` и `BonusRefCode` помечены как неиспользуемые в текущей версии (тег `json:"-"`)
- **Временные метки**: Модель включает поля для отслеживания времени создания и последнего обновления

## Устаревшие поля

### ProfitPrc
- **Описание**: Процент прибыли, связанный с рефералом
- **Статус**: Не используется в текущей версии
- **Причина**: Логика расчета прибыли перенесена в другие компоненты системы

### BonusRefCode
- **Описание**: Бонусный реферальный код, связанный с рефералом
- **Статус**: Не используется в текущей версии
- **Причина**: Функциональность бонусных кодов была упрощена или удалена

## Использование

Модель используется в системе для:

1. **Генерация кодов**: Создание уникальных реферальных кодов для пользователей
2. **Идентификация рефералов**: Связывание событий с конкретными реферальными кодами
3. **Управление пользователями**: Привязка реферальных кодов к учетным записям пользователей
4. **Аудит**: Отслеживание времени создания и изменения реферальных записей

## Связи с другими моделями

- **ReferralEvent**: События связываются с рефералами через поле `RefID`
- **ReferralConfig**: Конфигурации могут применяться к конкретным пользователям через `UserID`

## Примеры использования

### Создание нового реферального кода
```go
referral := &UserReferral{
    UserID:    &userID,
    RefCode:   generateUniqueCode(),
    CreatedAt: &now,
    UpdatedAt: &now,
}
```

### Поиск реферала по коду
```go
var referral UserReferral
err := db.Where("ref_code = ?", code).First(&referral).Error
```

## Миграция и совместимость

При работе с устаревшими полями следует учитывать:

- Поля `ProfitPrc` и `BonusRefCode` сохранены для обратной совместимости
- При создании новых записей эти поля можно игнорировать
- При обновлении существующих записей следует сохранять значения этих полей

# Общие особенности

## Временные метки
Все модели содержат поля `CreatedAt` и `UpdatedAt` для отслеживания времени создания и последнего обновления записей.

## JSON сериализация
Все модели поддерживают JSON сериализацию через теги `json`. Некоторые поля исключены из JSON (тег `json:"-"`).

## База данных
Все модели содержат теги `db` для маппинга полей на колонки базы данных.

## Nullable поля
Многие поля используют указатели (`*type`) для поддержки NULL значений в базе данных.

# Соглашения по именованию

- **Модели**: PascalCase (например, `ReferralEvent`)
- **Поля**: PascalCase (например, `CreatedAt`)
- **Константы**: PascalCase с префиксом (например, `ReferralEventTypeClick`)
- **JSON теги**: snake_case (например, `created_at`)
- **DB теги**: snake_case (например, `created_at`)

# Типы данных

## Основные типы
- `uint64` - для идентификаторов
- `int` - для перечислений и процентов
- `float64` - для денежных сумм
- `string` - для текстовых данных и JSON
- `*time.Time` - для временных меток (nullable)

## JSON поля
Некоторые поля хранят структурированные данные в JSON формате:
- `RewardSums` - суммы наград по валютам
- `FdSums` - суммы первого депозита по валютам
- `Data` - дополнительные данные событий

# Использование

Модели используются во всех слоях приложения:

1. **Repository слой**: Для работы с базой данных
2. **Service слой**: Для бизнес-логики
3. **Handler слой**: Для HTTP API и JSON сериализации
4. **NATS слой**: Для обмена сообщениями

# Миграции и совместимость

При изменении моделей следует учитывать:

- Обратную совместимость с существующими данными
- Миграции базы данных
- Версионирование API
- Устаревшие поля (помечены комментариями)
